Dataset metadata (applies to all published tables)

Source

Derived from Brightspace Organizational Units data sets (OrganizationalUnits, Parents, Ancestors, Descendants; optional Recent Access aggregated).

What an “Org Unit” is

Org units are the building blocks of Brightspace’s organization structure (can represent department/semester/course offering/section/group, etc.).

Time zone

All timestamp fields from the source are UTC (for example StartDate/EndDate, DateDeleted, LastAccessedDate).

PII posture

Low PII risk: all published tables are structural/metadata about org units.

The only dataset with user identifiers is Organizational Unit Recent Access (UserId), so we do not publish raw user rows—only optional aggregates by OrgUnitId.

Update policy

This is a one-time snapshot generated by your Spark pipeline (no incremental refresh).

CSV format (recommended to document)

UTF-8, header row included

Quoted fields (quoteAll=true) to avoid delimiter issues with names/codes

Nulls represented as empty fields

Key conventions

OrgUnitId is the primary identifier of an org unit (PK in source).

Relationships use OrgUnitId and ParentOrgUnitId / AncestorOrgUnitId / DescendantOrgUnitId (FK-like references).

Published tables
1) org_units_clean.csv

Purpose: The canonical, cleaned “dimension-like” table of org units (one row per org unit).

Grain: 1 row per OrgUnitId

Primary key: OrgUnitId

Where it comes from

Organizational Units dataset fields (OrgUnitId, Organization, Type, Name, Code, StartDate, EndDate, IsActive, CreatedDate, IsDeleted, DeletedDate, RecycledDate, Version, OrgUnitTypeId).

Column notes

StartDate / EndDate are availability window boundaries in UTC.

IsDeleted meaning includes soft deleted and recycled states.

Columns

OrgUnitId (int) — unique org unit identifier

OrgUnitTypeId (int) — identifier for the org unit type

Type (string) — org unit type name (e.g., Department, Semester, Section, Group)

Organization (string) — organization name

Name (string, nullable) — org unit name

Code (string, nullable) — org unit code

StartDate (timestamp, nullable, UTC) — availability start

EndDate (timestamp, nullable, UTC) — availability end

IsActive (bool) — whether the org unit is active

CreatedDate (timestamp, UTC) — create date

IsDeleted (bool, nullable) — whether deleted (soft deleted or recycled)

DeletedDate (timestamp, nullable, UTC) — when soft deleted

RecycledDate (timestamp, nullable, UTC) — when recycled

Version (bigint) — version of the content in the row

Name_norm (string) — derived: upper(trim/collapse(Name))

Code_norm (string) — derived: upper(trim/collapse(Code))

How to use

Join “fact-like” Brightspace datasets that have OrgUnitId (content, grades, enrollments, etc.) to get human-friendly Name/Type/Code.

2) org_units_lifecycle.csv

Purpose: Adds ready-to-use “status” flags for analytics and filtering.

Grain: 1 row per OrgUnitId (same as org_units_clean)

Columns added

is_within_dates (bool) — derived: now is between StartDate/EndDate (nulls treated as open-ended). Start/End are UTC in source.

is_available_now (bool) — derived: IsActive=true AND IsDeleted!=true AND is_within_dates=true

lifecycle_state (string) — derived categorical:

deleted_or_recycled (IsDeleted=true)

ended (EndDate < now)

future (StartDate > now)

active (IsActive=true)

inactive (fallback)

How to use

Filter to “currently available” org units without rewriting date logic each time.

3) dim_org_unit_type.csv

Purpose: A small dimension table mapping OrgUnitTypeId → Type.

Grain: 1 row per (OrgUnitTypeId, Type)

Columns

OrgUnitTypeId (int)

Type (string)

How to use

If you want to group by type using the numeric id (stable join key), use this as a lookup.

4) org_unit_parents_all.csv

Purpose: Direct parent relationships (edge list), including deleted relationships.

Grain: 1 row per parent-child relationship version

Columns

OrgUnitId (int) — child org unit id

ParentOrgUnitId (int) — parent org unit id

RowVersion (bigint) — ordering/versioning of the row (similar purpose to timestamps)

DateDeleted (timestamp, nullable, UTC) — when the relationship was deleted

How to use

Build hierarchy trees or detect org structure changes (if multiple rows exist per OrgUnitId over time).

5) org_unit_parents_active.csv

Purpose: Direct parent relationships currently active.

Definition

Subset of org_unit_parents_all where DateDeleted IS NULL.

How to use

Use this for “current org structure” joins and tree building.

6) org_unit_ancestors.csv

Purpose: Closure table mapping each org unit to all its ancestors (parents up the tree).

Grain: 1 row per (OrgUnitId, AncestorOrgUnitId) pair

Columns

OrgUnitId (int)

AncestorOrgUnitId (int) — ancestor (parent) org unit identifier

How to use

Fast rollups: “everything under Faculty X” by joining on AncestorOrgUnitId.

7) org_unit_descendants.csv

Purpose: Closure table mapping each org unit to all its descendants (children down the tree).

Grain: 1 row per (OrgUnitId, DescendantOrgUnitId) pair

Columns

OrgUnitId (int)

DescendantOrgUnitId (int) — child org unit identifier

How to use

Fast rollups: “count courses under Program Y” by joining on OrgUnitId → descendants.

8) org_unit_tree_snapshot.csv

Purpose: A “human-friendly” hierarchy snapshot with path strings for BI tools and CSV consumption.

Grain: 1 row per OrgUnitId

Key columns

OrgUnitId (int)

root_org_unit_id (int) — derived: top-most ancestor found via Parents traversal

depth (int) — derived: hops from node to root (0 = the node itself)

path_ids_str (string) — derived: OrgUnitId>Parent>...>Root

path_names_str (string) — derived: Name > ParentName > ... > RootName

plus selected metadata like Type, OrgUnitTypeId, is_available_now, lifecycle_state

How to use

Great for filtering and grouping in BI: “show all course offerings where path_names_str contains ‘Computer Science’”.

Use OrgUnitId to join this back to facts.

9) rollup_descendants_by_type.csv

Purpose: Precomputed rollups: for each org unit, how many descendants exist by type (and how many are available now).

Grain: 1 row per (OrgUnitId, OrgUnitTypeId)

Columns

OrgUnitId (int) — ancestor/root for the rollup

OrgUnitTypeId (int)

Type (string)

desc_total (int) — number of descendant links of that type

desc_available_now (int) — number of those descendants where is_available_now=true (derived from lifecycle logic)

How to use

Reporting without expensive closure joins: “departments ranked by active course offerings”.

Optional published tables (only if you include them)
10) org_unit_last_accessed.csv (aggregate-only)

Purpose: Latest access timestamp per org unit, without exposing user-level data.

Derived from

Organizational Unit Recent Access dataset, but only as an aggregate. Source contains UserId, which is why raw is not published.

Grain: 1 row per OrgUnitId
Columns

OrgUnitId (int)

last_accessed (timestamp, UTC) — max of LastAccessedDate

11) qc_type_id_conflicts.csv

Purpose: Data quality check showing any OrgUnitTypeId that maps to multiple Type strings (should usually be 1:1).

Relationship guide (how tables join)

Everything centers on OrgUnitId.

Parent tree:

org_unit_parents_active.OrgUnitId → child

org_unit_parents_active.ParentOrgUnitId → parent

Closure tables:

org_unit_ancestors.OrgUnitId ↔ org_units_clean.OrgUnitId

org_unit_ancestors.AncestorOrgUnitId ↔ org_units_clean.OrgUnitId

similarly for descendants

Tree snapshot:

org_unit_tree_snapshot.OrgUnitId ↔ org_units_clean.OrgUnitId

Important caveats to document

IsDeleted / DeletedDate / RecycledDate: represent soft-delete and recycle-bin lifecycle; historical backfill depends on the OrgUnit audit log.
