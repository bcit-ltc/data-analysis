OVERVIEW
================================================================================

This data dictionary documents eight processed datasets extracted from the BCIT 
Learning Management System. All datasets have undergone ETL (Extract, Transform, 
Load) processing, including deidentification of personally identifiable 
information (PII), standardization of column names, and comprehensive quality 
validation. The datasets span course content, assessments, organizational 
structures, and learning analytics from the institutional LMS.

DATASET CATALOG
================================================================================

1. CONTENT OBJECTS DATASET
   Location: etl-output/contentdata/contentobjects/data/
   
   DESCRIPTION:
   The Content Objects dataset represents the hierarchical structure of course 
   content within the LMS. This includes modules, topics, learning resources, 
   and other content items that make up courses.
   
   STATISTICS:
   - Total Records: 11,808,828
   - Total Columns: 25
   - Distinct Content Objects: 11,533,015 (97.7%)
   - Organizational Units Covered: 98,039
   - Date Range: 2008-2030 (based on start/end dates)
   
   KEY FIELDS:
   - content_object_id: Unique identifier for each content item (PRIMARY KEY)
   - org_unit_id: Links to organizational unit (course/section) (FOREIGN KEY)
   - title: Human-readable name of the content object
   - content_object_type: Type classification (80.2% Topic, 19.8% Module)
   - parent_content_object_id: Hierarchical parent reference (FOREIGN KEY)
   - location: URL or file path to content resource
   - start_date, end_date, due_date: Content availability scheduling
   - completion_type: How completion is tracked (99.2% Auto)
   - depth: Hierarchical level (45.8% at depth 2, 29.4% at depth 3)
   - sort_order: Display ordering within parent
   - tool_id: Associated LMS tool identifier
   - is_hidden, is_deleted: Visibility and deletion flags
   - ai_utilization: AI-assisted content indicator (99.99% = 0, minimal AI use)
   - last_modified: Timestamp of last modification
   
   DATA QUALITY:
   - Completeness: High quality with <1% missing values in critical fields
   - Duplicates: 94 duplicate content_object_id values (0.0008%)
   - Notable Missingness: 96.6% missing start_date, 98.5% missing end_date
   - Parse Success: >99.99% for all identifier fields
   - Outliers: 45,091 records (0.38%) with unusual sort_order values
   
   COMMON VALUES:
   - Most frequent titles: "Introduction", "Summary", "Videos", "References"
   - Completion Type: 99.2% auto-completion
   - Tools: 51000 (23.2%), 2000 (14.9%), 3000 (6.8%)

================================================================================
DATASET RELATIONSHIPS AND JOIN STRATEGIES
================================================================================

The eight datasets form an interconnected ecosystem representing the complete 
learning management system. Below are the recommended strategies for joining 
datasets to enable comprehensive analysis.

--------------------------------------------------------------------------------
PRIMARY RELATIONSHIP: ORGANIZATIONAL UNITS AS CENTRAL HUB
--------------------------------------------------------------------------------

The Organizational Units dataset serves as the central hub connecting most 
other datasets. Nearly all learning activities occur within an organizational 
context (course offering, section, or group).

JOIN PATTERN:
  organizational_units (org_unit_id)
    ├─→ content_objects (org_unit_id)
    ├─→ discussion_forums (org_unit_id)
    ├─→ grade_objects (org_unit_id)
    ├─→ quizzes (org_unit_id)
    ├─→ release_conditions (org_unit_id)
    └─→ role_details (org_unit_id)

SQL EXAMPLE:
  SELECT o.type, o.name as course_name, COUNT(c.content_object_id) as content_count
  FROM organizational_units o
  LEFT JOIN content_objects c ON o.org_unit_id = c.org_unit_id
  WHERE o.type = 'Course Offering' AND o.is_active = TRUE
  GROUP BY o.org_unit_id, o.type, o.name;

USE CASES:
- Course-level analytics across all content types
- Enrollment-based reporting (via organizational unit hierarchy)
- Cross-course comparisons and benchmarking
- Activity aggregation by department, term, or program

--------------------------------------------------------------------------------
CONTENT HIERARCHY: BUILDING THE LEARNING PATH
--------------------------------------------------------------------------------

Content Objects form a self-referential hierarchy that can be combined with 
release conditions to understand learning pathways and prerequisites.

JOIN PATTERN:
  content_objects (content_object_id)
    ├─→ content_objects (parent_content_object_id) [self-join for hierarchy]
    ├─→ content_service (linked via tool_id and object_id1)
    └─→ release_conditions (via result_id when result_tool_id = 37000)

SQL EXAMPLE:
  SELECT 
    parent.title as module_name,
    child.title as topic_name,
    child.depth,
    rc.name as prerequisite_type
  FROM content_objects child
  LEFT JOIN content_objects parent ON child.parent_content_object_id = parent.content_object_id
  LEFT JOIN release_conditions rc ON child.content_object_id = rc.result_id
  WHERE child.org_unit_id = [COURSE_ID]
  ORDER BY child.sort_order;

USE CASES:
- Constructing full course navigation trees
- Analyzing content depth and complexity
- Tracking prerequisite chains
- Identifying orphaned or unreachable content
- Understanding adaptive learning pathways

--------------------------------------------------------------------------------
ASSESSMENT ECOSYSTEM: GRADES, QUIZZES, AND RESULTS
--------------------------------------------------------------------------------

Grade Objects connect to Quizzes and other assessment tools, forming the 
complete assessment picture. Release Conditions can control access based on 
assessment performance.

JOIN PATTERN:
  grade_objects (grade_object_id)
    ├─→ quizzes (grade_object_id)
    ├─→ release_conditions (via id1 when pre_requisite_tool_id = 51000)
    └─→ organizational_units (org_unit_id)

SQL EXAMPLE:
  SELECT 
    go.name as grade_item_name,
    go.max_points,
    go.weight,
    q.quiz_name,
    q.time_limit,
    q.attempts_allowed,
    COUNT(rc.pre_requisite_id) as unlocks_count
  FROM grade_objects go
  LEFT JOIN quizzes q ON go.grade_object_id = q.grade_object_id
  LEFT JOIN release_conditions rc ON go.grade_object_id = rc.id1 
    AND rc.pre_requisite_tool_id = 51000
  WHERE go.org_unit_id = [COURSE_ID] 
    AND go.type_name = 'Numeric'
  GROUP BY go.grade_object_id, q.quiz_id;

USE CASES:
- Complete gradebook structure analysis
- Assessment design patterns (timing, attempts, weights)
- Grade-based prerequisite analysis
- Weighted grade calculations
- Assessment load distribution

--------------------------------------------------------------------------------
MULTIMEDIA INTEGRATION: LINKING VIDEO/AUDIO CONTENT
--------------------------------------------------------------------------------

Content Service data can be linked to Content Objects to analyze multimedia 
usage patterns.

JOIN PATTERN:
  content_service (content_id)
    └─→ content_objects (via tool_id = 699000 and object_id1)

APPROXIMATE SQL EXAMPLE:
  SELECT 
    co.title,
    co.org_unit_id,
    cs.type,
    cs.duration,
    cs.revision_size / 1048576 as size_mb,
    cs.required_transcribing
  FROM content_service cs
  INNER JOIN content_objects co 
    ON co.tool_id = 699000 
    AND CAST(co.object_id1 AS TEXT) LIKE '%' || CAST(cs.content_id AS TEXT) || '%'
  WHERE cs.type = 'Video';

NOTE: This join may require fuzzy matching or intermediate mapping tables 
depending on the exact relationship between content_id and object_id1.

USE CASES:
- Video/audio usage statistics by course
- Transcription coverage analysis
- Media file size and storage analysis
- Accessibility compliance tracking (transcription requirements)

--------------------------------------------------------------------------------
DISCUSSION PARTICIPATION STRUCTURE
--------------------------------------------------------------------------------

Discussion Forums link to Grade Objects when graded and can have release 
conditions controlling access.

JOIN PATTERN:
  discussion_forums (forum_id, org_unit_id)
    ├─→ grade_objects (via result_id)
    ├─→ release_conditions (via result_id when result_tool_id = 13000)
    └─→ organizational_units (org_unit_id)

SQL EXAMPLE:
  SELECT 
    df.name as forum_name,
    df.must_post_to_participate,
    go.name as grade_item_name,
    go.max_points,
    COUNT(rc.pre_requisite_id) as prerequisite_count
  FROM discussion_forums df
  LEFT JOIN grade_objects go ON df.result_id = go.result_id
  LEFT JOIN release_conditions rc ON df.result_id = rc.result_id 
    AND rc.result_tool_id = 13000
  WHERE df.org_unit_id = [COURSE_ID] AND df.is_deleted = FALSE
  GROUP BY df.forum_id, go.grade_object_id;

USE CASES:
- Graded vs. ungraded discussion analysis
- Participation requirement patterns
- Discussion-based prerequisite analysis
- Forum configuration best practices

--------------------------------------------------------------------------------
ADVANCED: MULTI-DATASET COURSE PROFILE
--------------------------------------------------------------------------------

Combining multiple datasets provides comprehensive course profiles.

COMPREHENSIVE JOIN EXAMPLE:
  SELECT 
    o.name as course_name,
    o.type as unit_type,
    COUNT(DISTINCT c.content_object_id) as content_items,
    COUNT(DISTINCT q.quiz_id) as quiz_count,
    COUNT(DISTINCT df.forum_id) as forum_count,
    COUNT(DISTINCT g.grade_object_id) as grade_items,
    SUM(CASE WHEN g.type_name = 'Numeric' THEN 1 ELSE 0 END) as graded_items,
    COUNT(DISTINCT rc.pre_requisite_id) as release_conditions,
    AVG(cs.duration) as avg_video_duration
  FROM organizational_units o
  LEFT JOIN content_objects c ON o.org_unit_id = c.org_unit_id 
    AND c.is_deleted = FALSE
  LEFT JOIN quizzes q ON o.org_unit_id = q.org_unit_id 
    AND q.is_active = TRUE
  LEFT JOIN discussion_forums df ON o.org_unit_id = df.org_unit_id 
    AND df.is_deleted = FALSE
  LEFT JOIN grade_objects g ON o.org_unit_id = g.org_unit_id 
    AND g.is_deleted = FALSE
  LEFT JOIN release_conditions rc ON o.org_unit_id = rc.org_unit_id
  LEFT JOIN content_service cs ON c.tool_id = 699000
  WHERE o.type = 'Course Offering' 
    AND o.is_active = TRUE
  GROUP BY o.org_unit_id, o.name, o.type
  ORDER BY content_items DESC;

USE CASES:
- Comprehensive course design analysis
- Institutional benchmarking
- Course quality metrics
- Resource utilization patterns
- Learning design consistency assessment

--------------------------------------------------------------------------------
ROLE-BASED ACCESS ANALYSIS
--------------------------------------------------------------------------------

Role Details can be analyzed in context of organizational units to understand 
permission structures.

JOIN PATTERN:
  role_details (org_unit_id)
    └─→ organizational_units (org_unit_id)

SQL EXAMPLE:
  SELECT 
    o.type as unit_type,
    r.role_name,
    r.is_cascading,
    r.show_in_grades,
    r.show_in_content,
    COUNT(*) as role_instances
  FROM role_details r
  INNER JOIN organizational_units o ON r.org_unit_id = o.org_unit_id
  GROUP BY o.type, r.role_name, r.is_cascading, r.show_in_grades, r.show_in_content;

USE CASES:
- Permission audit and compliance
- Custom role distribution analysis
- Access pattern identification
- Security configuration review

================================================================================
KEY IDENTIFIER MAPPINGS
================================================================================

ORGANIZATIONAL UNIT ID (org_unit_id):
  - Primary institution-wide identifier
  - Present in: organizational_units, content_objects, discussion_forums, 
    grade_objects, quizzes, release_conditions, role_details
  - Range: 6,605 to 1,214,715
  - Can represent courses, sections, groups, or organizational structures

CONTENT OBJECT ID (content_object_id):
  - Unique content item identifier
  - Present in: content_objects
  - Can be parent_content_object_id in same table
  - Links to release_conditions via result_id (when result_tool_id = 37000)

GRADE OBJECT ID (grade_object_id):
  - Unique grade item identifier
  - Present in: grade_objects
  - Can be parent_grade_object_id in same table
  - Links to quizzes via grade_object_id
  - Links to release_conditions via id1 (when pre_requisite_tool_id = 51000)

QUIZ ID (quiz_id):
  - Unique quiz identifier
  - Present in: quizzes
  - Links to grade_objects via grade_object_id
  - Links to release_conditions via id1 (when pre_requisite_tool_id = 51000)

FORUM ID (forum_id):
  - Unique discussion forum identifier
  - Present in: discussion_forums
  - Links to release_conditions via result_id (when result_tool_id = 13000)

RESULT ID (result_id):
  - Links to gradebook results
  - Present in: content_objects, discussion_forums, grade_objects, quizzes, 
    release_conditions
  - Often missing when items are not graded

TOOL ID (tool_id):
  - Identifies LMS tool type
  - Common values:
    * 2000: Assignments/Dropbox
    * 3000: Discussions
    * 37000: Content
    * 51000: Quizzes
    * 699000: Content Service (video/audio)

USAGE NOTES AND BEST PRACTICES
================================================================================

1. TEMPORAL ANALYSIS:
   - Many start_date, end_date, due_date fields have high missingness
   - Use creation_date and last_modified for temporal trends
   - Filter by is_active and is_deleted for current state analysis

2. HIERARCHICAL DATA:
   - Content Objects and Grade Objects contain self-referential hierarchies
   - Use recursive CTEs for full hierarchy traversal
   - depth field in Content Objects facilitates level-based analysis

3. PERFORMANCE OPTIMIZATION:
   - Large tables: content_objects (11.8M), organizational_units (1.1M), 
     grade_objects (1.6M), quizzes (701K)
   - Index on: org_unit_id, content_object_id, grade_object_id, quiz_id
   - Consider partitioning by org_unit_id for course-level analysis

4. MISSING DATA INTERPRETATION:
   - 100% missing: Field not used in BCIT's LMS configuration
   - 50-99% missing: Optional feature, check is_deleted flag
   - <50% missing: May indicate incomplete migration or data quality issue

5. VERSIONING:
   - version field present in multiple tables
   - Tracks configuration changes over time
   - Consider using MAX(version) for current state

6. TOOL IDENTIFIERS:
   - tool_id values are standardized across Brightspace/D2L platform
   - Reference mapping table recommended for human-readable tool names
